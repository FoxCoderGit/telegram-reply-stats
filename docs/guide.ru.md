# Статистика ответов в Telegram

Разовый анализатор личного чата от вашего аккаунта. Работает в Termux, Linux, Windows и macOS с Python 3.10+. Постоянный сервер и BotFather не нужны. В конце программа отключается от Telegram.

## Запуск в Termux

Распакуйте архив в отдельную папку и откройте её в Termux. Зависимости устанавливайте внутри Termux, не через системный Python Android.

```bash
pkg update
pkg install python
python -m pip install -r requirements.txt
python reply_stats.py --since 2026-01-01 --saved
```

Будет предложено войти в свой аккаунт и выбрать личный чат из списка. Готовый ZIP придёт в ваше «Избранное». Скачайте его и откройте `report.html` в браузере. Для последующего анализа здесь достаточно прислать `stats.json` или весь ZIP.

Для Linux / Windows / macOS последние две команды такие же; обычно используют виртуальное окружение (`python -m venv .venv`).

### Данные для входа

1. Откройте https://my.telegram.org → API development tools.
2. Создайте приложение (название, например, `Reply Statistics`, short name `replystats`; платформа Other).
3. Получите `api_id` и `api_hash`; скрипт запросит их при запуске. Это НЕ токен BotFather.
4. Затем введите свой номер телефона, код входа и пароль двухэтапной аутентификации, если он включён. Вводите их только в запущенном у себя скрипте.

Файл авторизации `private/account.session` хранится локально, в отчёт и архив он не попадает. Не отправляйте его другим: это доступ к вашему аккаунту. При повторном запуске авторизация обычно сохраняется; `api_id` и `api_hash` можно передать через переменные `TG_API_ID` и `TG_API_HASH`, чтобы не вводить каждый раз.

### Период и чат

```bash
python reply_stats.py --chat friend_username --since 2026-01-01 --until 2026-10-21 --saved
```

`--since` и `--until` включают указанные календарные дни в часовом поясе отчёта. Без `--since` читается вся доступная история; без `--until` — до момента запуска. Без `--chat` программа показывает список личных чатов. Можно указать username без `@` или известный числовой ID (если Telegram уже позволяет разрешить его из сессии).

Если Telegram доступен через VPN, запускайте скрипт при включённом VPN. Необязательно можно указать SOCKS5 без логина/пароля: `--proxy 127.0.0.1:1080`.

## Настройка сна

Откройте `config.json` любым текстовым редактором. Расписание сна и часовой пояс задаются отдельно для вас и собеседника. По умолчанию у обоих `Asia/Barnaul`, сон 00:00–08:00.

```json
{
  "report_timezone": "Asia/Barnaul",
  "me": {"timezone": "Asia/Barnaul", "sleep_start": "00:00", "sleep_end": "08:00"},
  "friend": {"timezone": "Europe/Moscow", "sleep_start": "01:00", "sleep_end": "09:00"},
  "long_gap_hours": 24,
  "min_period_samples": 5
}
```

Это фиксированное расписание, а не определение реального сна по статусу онлайн. Ночная переписка сохраняется; из ожидания вычитается только пересечение со сном того, кто отвечает. Если весь интервал пришёлся на сон, задержка без сна равна нулю, а реальная задержка сохранена отдельно. Одинаковые начало и конец (`00:00` / `00:00`) отключают исключение сна. Часовые пояса берутся из базы IANA.

Пример: сообщение в 23:50 и ответ в 08:20 при сне 00:00–08:00 дают 30 минут ожидания без сна.

## Что получится

- `report.html`: готовые графики и таблицы без внешних сервисов и интернет-зависимостей.
- `stats.json`: временные метки, роли me/friend, типы сообщений, все переходы, настройки, общая статистика и агрегаты. Подходит для передачи сюда и построения дополнительных графиков.
- `daily.csv`, `weekly.csv`, `monthly.csv`, `weekday.csv`, `hour.csv`: сводки для Excel или дальнейшего анализа.
- `responses.csv`: отдельные смены автора с задержками от первого и последнего сообщения серии.
- `summary.txt`: краткий итог.
- `telegram_stats.zip`: всё перечисленное в одном архиве.

Текст, имена, username, номера телефонов, идентификаторы пользователей и содержимое медиа не сохраняются. Даты и часы переписки в файлах остаются. В Telegram отправляется только ZIP и только в ваше «Избранное», если передан `--saved`. При ошибке отправки файлы остаются в папке `output`.

## Показатели и графики

Для обоих участников: количество сообщений и ответов, средняя задержка, медиана, 90-й процентиль, доля ответов до 5 минут и до часа, среднее с учётом всей ночи, задержка от последнего сообщения, типы сообщений и начала сессий. Графики: по дням, неделям, месяцам, дням недели и часам начала ожидания. Есть сравнение медиан соседних месяцев: где стало медленнее и на сколько минут. Для такого сравнения требуется минимум `min_period_samples` ответов в каждом месяце. Размеры выборок есть в таблицах и всплывающих подсказках. Графики прокручиваются горизонтально на телефоне, длинные таблицы раскрываются нажатием.

## Как это считается и что важно для интерпретации

1. Подряд идущие сообщения одного автора объединяются в серию. Одна смена автора = одно предполагаемое событие ответа; альбом из нескольких фотографий не создаёт несколько ответов.
2. Основная задержка отсчитывается от первого сообщения серии. От последнего также считается отдельная метрика, чтобы можно было сравнить обе методики.
3. Сон исключается по расписанию отвечающего; время отправки не означает время прочтения. Данные о прочтении и онлайн не собираются.
4. Пауза более `long_gap_hours` реальных часов от последнего сообщения считается границей сессии. Переход между авторами через такую паузу сохраняется с `long_gap=true` и не входит в основные средние. Есть отдельная сводка с включением таких переходов. Если после паузы снова написал тот же человек, начинается новая серия без события ответа.
5. Дата ответа в агрегатах — дата первого сообщения ожидающей серии в `report_timezone`. Число сообщений группируется по собственной дате отправки. Поэтому сообщения и ответы в одной строке не обязаны совпадать по количеству. Неделя начинается с понедельника, день недели: 0=Пн ... 6=Вс; час — час начала ожидания в часовом поясе отчёта, не локальный час каждого участника.
6. Последняя серия показана как текущее ожидание на конец выбранного периода и не включается в среднее. Это не доказательство игнорирования и не полный подсчёт «неотвеченных вопросов»; содержание не анализируется. Первое сообщение периода может продолжать разговор за его границей; оно не имеет известного предшественника. Удалённые сообщения не восстанавливаются.
7. Нулевое количество ответов даёт пустую метрику, а не нулевую задержку. Пустые календарные периоды присутствуют в данных, графики имеют разрывы. Среднее рассчитывается по событиям ответа, а не как среднее дневных средних.
8. Медиана — типичное время, p90 — время, в которое уложились примерно 90% ответов (линейная интерполяция процентиля). Маленькие выборки ненадёжны; дневные выбросы сами по себе ничего не доказывают. Сравнение месяцев описательное, без проверки статистической значимости.
9. API Telegram возвращает только доступную этому аккаунту историю обычного облачного чата; секретные чаты не поддерживаются. Вход может показываться в Telegram как новая сессия. Программа не отправляет сообщений собеседнику и не вызывает подтверждение прочтения.

## Проверка без аккаунта и пересчёт

```bash
python reply_stats.py --demo --output demo
python -m unittest -v test_reply_stats.py
```

Демонстрационные данные вымышлены и подписаны в отчёте. Никакого входа в Telegram нет.

Изменили расписание сна? Историю повторно скачивать не нужно:

```bash
python reply_stats.py --reanalyze output/stats.json --output recalculated
```

Этот режим работает без Telegram и не отправляет файлы даже при `--saved`. Для новой автоматической отправки используйте обычный запуск. Повторная выгрузка всей истории позволяет учесть текущие доступные сообщения, включая удаления; постоянный мониторинг в этой версии не требуется.

## Проверено при подготовке

Проверены расчёты ночи, перехода через полночь и несколько дней, разных часовых поясов, перевода часов, серий сообщений, длинных пауз, пустой истории, атрибуции по месяцам и состава ZIP. Проверены генерация демонстрационного отчёта и офлайн-пересчёт. Вход в реальный аккаунт и отправка в «Избранное» требуют запуска на вашем устройстве и здесь не проверялись.

Документация: https://core.telegram.org/api/obtaining_api_id ; https://docs.telethon.dev/en/stable/modules/client.html .
